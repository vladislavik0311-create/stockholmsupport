# Настройка отдельного входа и главного администратора

Netlify этим обновлением не меняется и автоматически ничего не публикуется. Это изменения только в локальных файлах проекта.

## 1. Обновить структуру Supabase

В Supabase открой **SQL Editor → New query**, вставь целиком файл `database/admin_access_migration.sql` и нажми **Run**. Это добавит роль `owner`, права администраторов, шаблоны ролей и вход по логину.

## 2. Создать главный аккаунт `adm`

На самом сайте через обычную регистрацию создай аккаунт:

- Логин: `adm`
- Почта: твоя действующая почта
- Пароль: `love123`
- Повтор пароля: `love123`

Если Supabase требует подтверждение почты, сначала подтверди её по письму.

Затем в Supabase SQL Editor выполни:

```sql
update public.profiles
set role = 'owner',
    permissions = '{}'::jsonb,
    admin_title = 'Главный администратор'
where lower(username) = 'adm';
```

Запрос должен изменить ровно одну строку. Если изменено 0 строк, проверь, что аккаунт `adm` зарегистрирован и подтверждён.

## 3. Развернуть защищённую функцию создания администраторов

Для создания других аккаунтов и установки им паролей нужен серверный вызов Supabase Edge Function. Ключ `service_role` не помещается в браузер и не добавляется в `supabase-config.js`.

Из корневой папки проекта, где лежит каталог `supabase`, выполни через Supabase CLI:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy admin-manager
```

`YOUR_PROJECT_REF` возьми из Supabase → Project Settings → General → Reference ID. В среде Edge Functions используются серверные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`.

## 4. Вход в админку

В верхней панели сайта нажми **«Админ-вход»**. Введи:

- Логин: `adm`
- Пароль: `love123`

После входа открой раздел «Администрация». У аккаунта `adm` роль `owner` — это главный администратор с полным доступом без ограничений.

**Безопасность:** `love123` — временный пароль, он слабый. После первого входа сразу поменяй его в настройках аккаунта на длинный уникальный пароль. Пароль не хранится в исходниках сайта.

## 5. Создание других администраторов

В разделе «Администрация» главный администратор может:

- создать отдельный аккаунт администратора;
- задать ему логин, почту и пароль;
- указать название его должности;
- выбрать конкретные разрешения;
- создать шаблоны должностей и применять их при создании новых администраторов;
- менять разрешения и пароль уже созданных администраторов.

Роль `owner` нельзя выдать через обычную форму создания администратора. Её может назначить только владелец через защищённую процедуру в базе.
