# Stockholm Support — бесплатно, без Render

Сайт размещается на **Cloudflare Pages Free**, а аккаунты и данные — в **Supabase Free**. Render и постоянно работающий Node.js-сервер не нужны. Платный домен не нужен: Cloudflare выдаст адрес `https://имя.pages.dev`.

## 1. Создай базу и авторизацию Supabase

1. Зарегистрируйся на https://supabase.com/ и создай проект на плане **Free**.
2. Открой **SQL Editor → New query**, вставь весь файл `database/supabase_schema.sql` и нажми Run.
3. Открой **Project Settings → API**. Скопируй Project URL и публичный `anon` / `publishable` key.
4. В файле `supabase-config.js` замени значения `https://ВАШ-ПРОЕКТ.supabase.co` и `ВАШ_PUBLISHABLE_ANON_KEY` на свои.
5. В Supabase открой **Authentication → URL Configuration**. Позже добавь туда адрес Cloudflare Pages в Site URL и Redirect URLs.
6. В **Authentication → Providers → Email** настрой подтверждение почты. Для Discord включи провайдера Discord; в Discord Developer Portal укажи callback URL, который покажет Supabase на странице настроек провайдера.

Важно: в `supabase-config.js` разрешено вставлять только публичный anon/publishable key. **Никогда не вставляй `service_role` или secret key в сайт**.

## 2. Опубликуй сайт на Cloudflare Pages

1. Создай бесплатный аккаунт на https://dash.cloudflare.com/.
2. Открой **Workers & Pages → Create → Pages → Connect to Git**.
3. Подключи GitHub и выбери репозиторий, в который загружены файлы из этой папки.
4. Если загружаешь весь архив в репозиторий, укажи папку `stockholm_support_public` как **Root directory**. Если содержимое папки загружено прямо в корень репозитория, оставь Root directory пустым.
5. Для обычного HTML-сайта выбери **No framework**. Build command оставь пустой, а **Build output directory** укажи `.`.
6. Нажми Save and Deploy. Cloudflare выдаст публичный адрес `https://имя-проекта.pages.dev`.
7. Скопируй этот адрес в Supabase → Authentication → URL Configuration → Site URL и Redirect URLs.

Можно также загрузить готовую папку через Direct Upload в Cloudflare Pages.

## 3. Назначь себя администратором

1. Открой опубликованный сайт и зарегистрируй аккаунт.
2. В Supabase открой **SQL Editor** и выполни запрос, заменив почту на свою:

```sql
update public.profiles set role='admin' where email='ТВОЯ_ПОЧТА';
```

3. Выйди из аккаунта и войди снова.

## Что уже подключено в этой версии

- Статический сайт: HTML/CSS/JS, без Render и без Node-сервера.
- Supabase Auth: регистрация по логину, почте и паролю; вход в текущей версии — по почте и паролю.
- Профили пользователей и роли support / senior / admin.
- PostgreSQL-таблицы для подветок, заданий, событий, объявлений и журнала действий.
- Row Level Security (RLS): чтение профиля ограничено своим аккаунтом и администратором; основные рабочие данные доступны авторизованным, изменять их может администратор.
- Discord OAuth можно включить в настройках Supabase и Discord.

## Ограничения бесплатного тарифа

Supabase Free включает 500 МБ базы данных, 5 ГБ исходящего трафика и до 50 000 активных пользователей в месяц; бесплатный проект может приостанавливаться после недели низкой активности. Проверь актуальные лимиты перед запуском: https://supabase.com/pricing. Источник: https://supabase.com/docs/guides/platform/free-project-pausing.

Cloudflare Pages Free позволяет до 500 сборок в месяц; статические файлы раздаются без отдельной платы в пределах условий сервиса. Источник: https://developers.cloudflare.com/pages/platform/limits/.

Бесплатность действует, пока проект укладывается в бесплатные лимиты. Не подключай платные тарифы и дополнения. Не добавляй платёжный способ, если платформа этого не требует для выбранной бесплатной функции.

## Важные замечания

- Вход по имени пользователя пока не реализован: в этой версии вход выполняется по почте. Это сделано намеренно, чтобы не раскрывать почтовые адреса пользователей через публичный поиск по логину. Регистрация всё ещё принимает логин и почту.
- Полноценная логика всех разделов (таблицы ПТ, переаттестации, учёт часов, достижения, административные формы и т. д.) требует следующих этапов разработки. Сейчас подключены фундамент авторизации и структура базы.
- Перед открытием регистрации всему сообществу настрой подтверждение почты и правила доступа.

## Локальный просмотр

Из папки с файлами сайта запусти `python -m http.server 8000`, затем открой `http://localhost:8000`. Не открывай `index.html` напрямую через `file://`.


## Обновление профиля и настроек аккаунта

В обновлённой версии в меню ника есть пункты «Настройки» и «Выйти». В настройках можно менять ник, почту, пароль, аватар и баннер. Для Discord-авторизации в меню профиля отображается подпись «Юзер ДС».

Чтобы включить новые поля и загрузку изображений:
1. Открой Supabase → SQL Editor.
2. Вставь и выполни обновлённый файл `database/supabase_schema.sql` (его можно выполнять повторно).
3. Проверь, что в `supabase-config.js` указаны правильные Project URL и публичный anon/publishable key.
4. В Supabase → Authentication → Providers включи Discord и проверь callback URL, если ещё не сделал этого.

Изображения загружаются в публичный bucket `profile-media`; пользователи могут загружать файлы только в собственную папку. Допустимые форматы: PNG, JPEG, WebP и GIF для аватара; максимальный размер — 5 МБ для аватара и 8 МБ для баннера.
