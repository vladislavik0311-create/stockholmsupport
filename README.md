# Stockholm Support — обновлённое рабочее пространство

Новая версия сохраняет тёмно-зелёный дизайн Jade Palace и добавляет 14 разделов с выдвижной навигацией. Меню разделов скрыто до нажатия на кнопку ☰ слева сверху. Переключение страниц анимировано.

## Что есть в интерфейсе

- Главная: приветствие, показатели саппортов и вышки, задания недели по подветкам, кураторы, уведомления, участники, активность, события и блок «Быстрее десяти».
- Задания: фильтр по подветкам; администратор может добавлять задания.
- Статистика: общая сводка и прогресс подветок, выбор периода.
- Переаттестации: история, проводивший, результат и следующая дата.
- Таблицы: отдельные вкладки «Таблица» и «ПТ».
- Мероприятия и собрания: списки и формы добавления.
- Документы: общие материалы и материалы подветок.
- Колесо фортуны: редактируемые сектора и относительные веса/вероятности.
- Шар предсказаний: вопрос и случайный ответ.
- Администрация: назначение ролей, подветки, журнал действий и сообщение зайчика.
- Трекер заданий, ивенты для вышки и достижения.
- Зайчик-помощник справа снизу.
- Вход, регистрация, Discord OAuth, меню профиля, настройки, аватар и баннер.

## Подключение Supabase

1. В `supabase-config.js` укажи свой Project URL и публичный anon/publishable key.
2. В Supabase → SQL Editor выполни `database/supabase_schema.sql`.
3. В Supabase → Authentication → Providers включи Email и Discord.
4. В Discord Developer Portal укажи callback URL, который показывает Supabase для Discord OAuth.
5. В Supabase → Authentication → URL Configuration добавь адрес опубликованного сайта в Site URL и Redirect URLs.
6. Зарегистрируй свой аккаунт, затем назначь себе администратора SQL-запросом:

```sql
update public.profiles set role='admin' where email='ТВОЯ_ПОЧТА';
```

Для загрузки аватаров и баннеров используется Storage bucket `profile-media`, который создаётся SQL-схемой.

## Важное о данных

В этой сборке Supabase используется для регистрации/входа, Discord OAuth и профилей. Рабочие записи новых разделов (таблицы, ПТ, история переаттестаций, собрания, документы, достижения, настройки колеса и часть журналов) пока сохраняются в `localStorage` текущего браузера. Они не синхронизируются между участниками и устройствами и не являются общей базой команды. Перед реальным запуском для всей команды нужно подключить эти разделы к отдельным таблицам Supabase и настроить RLS-права.

Вход по почте работает через Supabase Auth. Вход по логину вызывает RPC `get_email_by_username`; для него нужна отдельная серверная Edge Function с безопасной проверкой логина. Не создавай публичную SQL-функцию, которая просто возвращает email по логину: это раскроет адреса пользователей. До подключения Edge Function используй почту.

## Публикация

Загрузи содержимое папки `stockholm_support_public` на Netlify или Cloudflare Pages. Build command не требуется, publish directory — папка с `index.html`.

Никогда не вставляй `service_role` или secret key в клиентские файлы. Используй только публичный anon/publishable key.

## Отдельный вход администратора

См. `ADMIN_SETUP_RU.md`: миграция `database/admin_access_migration.sql`, создание владельца `adm` и развёртывание Edge Function `admin-manager`.
